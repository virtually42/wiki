## [2026-05-29] implement | build.mill migrated to dm catalog (DM-002)

`/p/hg/safetensors-scala/build.mill` switched from inline `object V`
versions to `build.deps.Deps.*` references from the auto-generated
`deps/Dependencies.mill`. Catalog: `/p/hg/dependency-manager/deps/`.

### Surface migrated

3 external Maven libraries — `scodec-core`, `munit`,
`munit-scalacheck` — across `SafeTensorsCommon` (the production
mvnDeps for the scodec runtime dep) and `SafeTensorsTestSources`
(shared test deps).

- `mvn"org.scodec::scodec-core::${V.scodec}"` →
  `build.deps.Deps.scodecCore`
- `mvn"org.scalameta::munit::${V.munit}"` → `build.deps.Deps.munit`
- `mvn"org.scalameta::munit-scalacheck::${V.munitScalaCheck}"` →
  `build.deps.Deps.munitScalacheck` (note the case fold:
  `Check` → `check`).

`object V` retains `scalaVersions`, `scalaJS`, `scalaNative`,
`organization`, `artifact`, `projectVersion`. The inline comment
in `object V` notes that the scodec-pin (2.3.3, palladium
resolution) is now held by the central catalog.

### scodec-pin transfer

The pin moved from inline `V.scodec = "2.3.3"` to
`/p/hg/dependency-manager/deps/libs.versions.toml`
(`scodec-core = "2.3.3"`). Version unchanged; *owner* of the
pin moved. Renovate's customManagers will surface any upstream
bump as a PR; the constraint is enforced via the catalog rather
than inline. Future drift is caught by `dm verify` / `dm promote`.

### `deps/package.mill` anchor

One-line file: `package build.deps`. Required by Mill 1.x to
discover sibling `Dependencies.mill` as a helper file. Same
pattern slm and toolbox adopted on their migrations.
