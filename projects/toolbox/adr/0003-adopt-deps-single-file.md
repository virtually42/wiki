## Context

[[tech/decisions/deps-single-file]] (accepted 2026-05-24, global
scope) requires Scala projects to declare dependencies in a
single `deps/Dependencies.mill` file with inline `mvn"…"`
coordinates.

Up to 2026-05-29, `toolbox` deviated: `build.mill`'s `object V`
declared 8 library versions inline (the original 8 — `kyoCore`,
`catsEffect`, `fs2`, `slm`, `osLib`, `pprint`, `sourcecode`,
`munit`; the post-migration count is 10 once `fs2` fans out to
`fs2Core` + `fs2Io` and `munit-cats-effect` is added), no
`deps/Dependencies.mill` file existed. The deviation was
recorded in
[[projects/toolbox/adr/0002-deviate-deps-single-file]] with
expiry conditions tied to monorepo embedding.

On 2026-05-29, the dm dependency manager project closed the
loop differently. dm produces a per-consumer
`deps/Dependencies.mill` from a central TOML catalog,
sidestepping the monorepo-embedding precondition. Toolbox
migrated to consume `build.deps.Deps.*` from the dm-generated
file across all 9 call-site groups (script JVM/JS/Native, vfs
JVM/JS/Native, procOslib JVM/Native, procFs2 JVM,
procKyo JVM/JS, example JVM, plus the shared `ToolboxTestSources`
munit reference). See
[[projects/dependency-manager/log]] §"toolbox migrated to dm
catalog (DM-001)" for the migration record.

This ADR records the resulting conformance with
[[tech/decisions/deps-single-file]], with a narrow exception
for platform versions and project-internal `no.virtual-architect`
self-references.

## Decision

Adopt [[tech/decisions/deps-single-file]] for **external Maven
library coordinates**. These now live in
`/p/hg/toolbox/deps/Dependencies.mill`, auto-generated by
`dm regen` from the catalog at
`/p/hg/dependency-manager/deps/`.

Continue to inline:

- **Platform versions** (`scalaVersions`, `scalaJS`,
  `scalaNative`) — dm boundary.
- **Project-internal metadata** (`organization`,
  `projectVersion`) — not Maven coordinates.
- **Self-references**, i.e. inter-module
  `no.virtual-architect::*` `mvn` literals that consume
  publishLocal artefacts of sibling modules. Toolbox's modules
  currently do not need this (cross-module deps go through
  `moduleDeps`, not `mvnDeps`), but the rule is stated for
  forward-compatibility.

The Mill 1.x discovery anchor `deps/package.mill` (one line:
`package build.deps`) is required for Mill to discover the
generated `Dependencies.mill`. Toolbox's anchor was added on
2026-05-29 as part of the DM-001 migration.

## Consequences

- `deps-single-file`'s automation goal is met for all 10
  external Maven deps: Renovate parses the central catalog;
  `dm regen` rewrites `toolbox/deps/Dependencies.mill`; Mill
  picks up the change at the next compile.
- Cross-project version drift on external deps is eliminated
  by construction — the catalog is shared with slm and
  safetensors-scala, so common deps (`munit`,
  `sourceline-manager`) cannot drift apart.
- Narrow exception remains for platform versions; documented
  in the `compliance.exceptions` block above. Severity `low`
  because the exception is principled (Maven model boundary)
  rather than incidental.
- `meta/drift.md` should now flag this project as **adopting**
  `deps-single-file` (with the platform-versions exception),
  not deviating.
- The "second-deviation precedent" concern from ADR-0002
  ("If a third project lands with the same shape, consider
  whether the global decision needs to grow a 'standalone
  pre-embedding' carve-out") is now moot — all three v1
  consumers adopt via the same dm mechanism with the same
  exception shape.

## Alternatives Considered

- **Adopt unconditionally including `object Platform`.**
  Rejected: would require either inventing a new YAML/TOML
  shape for platform versions and a per-shape Renovate manager
  to bump them, or hand-rolling the bump path. dm explicitly
  defers this; cloning the rejection of premature scope is
  the right call.
- **Keep the original deviation.** Rejected: the migration
  closed the deviation's core concern (extraction had no
  payoff while standalone, and there was no shared catalog
  to attach to). Honest re-classification is better than
  ADR rot.
- **Single rewrite of ADR-0002 instead of supersession.**
  Rejected: the new adoption rests on a different mechanism
  (dm catalog) than the deviation's reasoning chain (monorepo
  embedding timeline). Two ADRs keep the reasoning history
  legible.
