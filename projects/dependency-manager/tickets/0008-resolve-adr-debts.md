## Goal

Each of the three consumer projects has a normative claim about
how it relates to [[tech/decisions/deps-single-file]]. After
DM-001 / DM-002 land, those claims are partially or fully
inaccurate:

- **sourceline-manager**: wiki ADR-0002 says "deviate (no
  Dependencies.mill file)". Post-migration, a `Dependencies.mill`
  exists (auto-generated) and is consumed. The deviation is
  partially expired.
- **toolbox**: wiki ADR-0002 (currently same shape as slm's).
  Same partial expiry after DM-001.
- **safetensors-scala**: in-tree
  `/p/hg/safetensors-scala/docs/adr/0001-inline-versions.md` says
  "deviate (inline `object V`)". Same partial expiry after DM-002.
  Note: safetensors has no wiki-side ADR mirror.

This ticket realigns the normative surface so every consumer's ADR
accurately describes its post-migration relationship to
`deps-single-file`. The pattern across all three: **adopt for the
library coordinates half (now sourced via dm), retain a narrower
deviation for the platform versions half (which dm intentionally
does not manage)**.

## Notes

**The platform-versions exception is non-trivial** — `deps-single-file`
shows the canonical layout including `object Platform`. None of the
three consumers carry `object Platform`; they all retain
`V.scalaVersions`, `V.scalaJS`, `V.scalaNative` inline in
`build.mill`. The new ADRs should explicitly:

1. Adopt the `object Deps` half (now conforming via dm).
2. Document the deviation for `object Platform` (Renovate's Maven
   model does not cover platform versions; mixing shapes is wrong).
3. Cite the dm `Platform` open question (see DM-007 §Open Questions)
   as the deferral location.

**Why this is one ticket and not three** — the three changes share
a single rationale and should land coherently. Splitting per-project
risks a multi-step staircase where the wiki briefly shows incoherent
normative claims between commits.

**Wording template** for the adopt-with-exception ADR:

```markdown
## Decision

Adopt [[tech/decisions/deps-single-file]] for external Maven
library coordinates. These now live in `deps/Dependencies.mill`,
auto-generated by `dm regen` from the central catalog at
`/p/hg/dependency-manager/deps/`.

Continue to inline platform versions (`scalaVersions`, `scalaJS`,
`scalaNative`) in `build.mill`'s `object V`. dm intentionally does
not manage platform versions — they are not Maven coordinates in
the same shape and Renovate's Maven managers do not cover them.
See [[projects/dependency-manager/designs/dm-architecture]] for
the platform-versions deferral rationale.
```
